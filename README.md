# CarePulse — Healthcare Readmission Risk Pipeline

An end-to-end data engineering pipeline on AWS, built to predict 30-day hospital
readmission risk from synthetic patient data — designed as a portfolio project
targeting Data Engineer / ETL / PySpark roles on AWS + Snowflake.

**Full build log, every decision, every bug, and interview Q&A:** see
[`CarePulse_Notes.html`](./CarePulse_Notes.html) — open it in a browser for a
searchable, phase-by-phase walkthrough of the entire build.


## Architecture
```
Synthea (synthetic patient data generator)
   |
   v
Amazon S3 (raw zone) --[S3 event]--> AWS Lambda (validate.py)
   |                                     |
   |                              accepted / rejected -> quarantine/
   v
AWS Glue (PySpark, transform_table.py)
   |
   v
Amazon S3 (curated zone, Parquet)
   |
   v
Snowflake (planned — Phase 3)
```


All infrastructure is defined in Terraform (`infra/`), with remote state in S3
and locking via DynamoDB.

## Tech stack

- **Data generation:** [Synthea](https://github.com/synthetichealth/synthea) — realistic, fully synthetic patient records (no PHI)
- **Storage:** Amazon S3 (raw + curated zones)
- **Validation:** AWS Lambda (Python, boto3) — schema validation, quarantine on failure
- **Transformation:** AWS Glue (PySpark) — CSV to Parquet, parameterized across all six source tables
- **Infrastructure as Code:** Terraform — S3, IAM, Lambda, Glue, remote state (S3 + DynamoDB locking)
- **Planned:** Snowflake (data warehouse), SageMaker (readmission model)

## Notable engineering decisions

- **Parameterized Glue job** — one script (`transform_table.py`) handles all six
  source tables via a runtime argument, instead of one script per table.
- **Terraform remote state** — S3 backend + DynamoDB locking, set up explicitly
  to demonstrate safe concurrent-apply handling.
- **Measured, not assumed, tuning** — the largest source table (7.7GB) was run
  with default/minimal Glue worker settings first to get a real baseline before
  any optimization; it completed well within budget, avoiding unnecessary
  over-provisioning. Details in the notes.

## Disclaimer

All patient data is fully synthetic, generated by Synthea. This project is an
educational/portfolio demonstration — not a clinical tool, and not validated
for any real-world healthcare use.
